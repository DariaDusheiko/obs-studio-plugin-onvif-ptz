Профессиональные функции

Разработано специально для эфирного вещания

Плагин решает ключевые проблемы аппаратных систем управления PTZ-камерами, избавляя от лишних контроллеров.

Глобальные горячие клавиши

Регистрирует горячие клавиши на каждую камеру. Движение выполняется только пока клавиша зажата, а при отпускании камера мгновенно останавливается.

Асинхронные SOAP/XML запросы

Все сетевые операции выполняются в отдельном фоновом потоке. Полностью исключены микрофризы интерфейса OBS Studio при отправке PTZ-команд.

WS-Security Digest авторизация

Безопасная аутентификация по стандарту WSSE с использованием криптографических SHA1 дайджестов и уникальных Nonce меток.

Кастомные пресеты (1-8 слотов)

Легкое управление сценой. Запоминайте и переназывайте пресеты прямо в плагине или подтягивайте уже существующие конфигурации из памяти самой камеры.

Интеграция GStreamer Pipeline

Декодирование RTSP видеопотока через асинхронный GStreamer с выводом в формате NV12 прямо в рендер-движок OBS. Высокая частота кадров.

Поддержка горячей замены

Плагин отслеживает события OBS `source_create` и `source_destroy`, динамически обновляя выпадающие списки выбора камер без перезапуска приложения.

Шаг за шагом

Руководство по быстрой установке

Как разместить плагин и настроить его для стриминга.

А

Размещение файлов в системе (macOS)

Переместите полученный после сборки бандл .so в папку плагинов OBS Studio по пути:
~/Library/Application Support/obs-studio/plugins/

Б

Конфигурация источника камеры

Добавьте новый источник ONVIF Camera в OBS. Заполните IP-адрес вашей камеры, пароль ONVIF-аккаунта, и выберите режим обнаружения URL потока. Профиль 0 — для основного HD потока, 1 — для субпотока.

В

Настройка прав macOS (Важно для удержания клавиш)

Для корректной работы хоткеев на macOS перейдите в:
Системные настройки → Конфиденциальность и безопасность → Мониторинг ввода.
Включите тумблер для OBS.app и полностью перезапустите приложение.

Решение возможных проблем

Рекомендации разработчиков плагина при возникновении неполадок с подключением или вещанием.

Проблемы с сетевым подключением

  • «Тайм-аут соединения»: проверьте пинг до IP адреса камеры, правильность указания порта ONVIF (по умолчанию 80).
  • «Аутентификация не удалась»: проверьте учетные данные, созданные на камере именно в разделе пользователей ONVIF (они могут отличаться от админ-панели веб-интерфейса).

Ошибки видеопотока

  • Черный экран: проверьте RTSP-порт (обычно 554). Переключите транспортный протокол на TCP вместо UDP.
  • Подтормаживание кадров: увеличьте размер буфера latency_ms в свойствах источника, смените кодек на H.264.

Логирование отладки

Запустите OBS с терминала с префиксами: --verbose --log-level debug.
Логи плагина будут помечаться тегами [ONVIF] и [TRACKING] в окне вывода.

Раздел инженера

Архитектурный справочник C++

Кодовая база плагина разделена на 3 независимых компонента, общающихся через строго типизированные API интерфейсы.

1

Клиент ONVIF (onvif_client.cpp)

Отвечает за сериализацию SOAP/XML шаблонов, генерацию WS-Security дайджестов и отправку HTTP-команд через curl.

2

Виджет PTZ Dock (ptz-dock.cpp)

Пользовательский интерфейс на базе Qt UI, интегрированный как встраиваемая док-панель OBS. Потокобезопасная синхронизация.

3

Источник OBS Source (onvif-ptz-source.cpp)

Регистрирует тип источника в OBS. Запускает конвейер декодирования GStreamer и передает кадры NV12 в движок OBS.

class ONVIFClient API C++ / CMake
class ONVIFClient {
// Конструктор инициализирует Curl и строит URL-адреса сервисов ONVIF
public:
ONVIFClient(std::string host, std::string user, std::string pass, int port = 80);
~ONVIFClient();
// Основные API запросы к камере
bool getDeviceInformation();
bool getProfiles();
std::string getRTSPStreamURL();
// Команды PTZ (ContinuousMove)
bool ptzContinuousMove(float vx, float vy, float vz);
bool ptzStop();
bool ptzGoToHome(float speed = 0.5f);
// Генерация WSSE Дайджеста авторизации
std::string generatePasswordDigest(std::string nonce, std::string created, std::string pass);
};
